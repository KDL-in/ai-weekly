### 大型语言模型 0.33
*llm 0.33*

- **作者**：Simon Willison
- **信源**：Simon Willison
- **时间**：2026-08-22T17:01:16
- **亮点**：
  - 升级至 OpenAI Python 库 3.x，HTTP 客户端从 httpx 迁移至 httpx2
  - 嵌入模型新增 --key 参数支持，实现每次调用的密钥传递
  - llm prompt 模板可重复组合，支持模型配置与提示词模板分离复用

Simon Willison 发布 llm 0.33 版本，带来多项重要更新。该版本将 OpenAI Python 库升级至 3.x，并将 HTTP 客户端依赖从 httpx 迁移至 httpx2，这是继 0.32.1 快速修复后的更全面解决方案。llm embed 和 llm embed-multi 命令新增 --key 参数，Python 的 EmbeddingModel.embed()、embed_multi()、Collection.embed() 和 embed_multi() 方法也支持 key= 参数，可将每次调用的密钥传递给嵌入插件而不改变共享模型状态，现有插件通过兼容回退继续工作。llm prompt 的 -t/--template 参数现在可重复使用以按顺序组合模板，支持将模型配置与提示词模板分离组合。此外，支持推理能力的 Responses API 模型新增 reasoning_summary 选项，可选 auto、concise 和 detailed 值。

[原文](https://simonwillison.net/2026/Aug/22/llm/)

*smolmachines / smolvm as a sandbox for untrusted Python & JavaScript*

- **作者**：Simon Willison
- **信源**：Simon Willison
- **时间**：2026-08-19T23:16:00
- **亮点**：
  - Claude Code for web 环境因缺少 /dev/kvm 无法直接运行 smolvm，暴露了嵌套虚拟化的限制
  - Claude Fable 自主切换到 GitHub Actions runner 执行真实测试，展示了智能体的环境适应能力
  - 测试目标明确：限制 CPU/RAM、禁止网络、仅允许指定文件访问，面向数据转换等用户提交任务场景

Simon Willison 记录了一次由 Claude Fable 5 在 Claude Code for web 中执行的研究任务：评估 smolmachines/smolvm 能否作为运行不可信 Python 和 JavaScript 代码的快速安全沙箱，要求限制 RAM 与 CPU 时间（防止死循环）、无网络访问、仅允许访问指定文件。由于 Claude Code for web 容器本身是 Firecracker 客户机，缺少 /dev/kvm 和虚拟化 CPU 标志，无法运行 smolvm。Claude Fable 随即采用 Plan B：利用 GitHub Actions 的 ubuntu runner 暴露的 /dev/kvm，在临时分支上通过 workflow 直接运行完整测试。Willison 称赞这是对环境限制的创造性解决方案，也体现了 Fable 的主动执行能力。

- **时间**：2026-08-19T22:46:07

  - 指出新的限制因素是工程师的认知容量而非代码产出速度

Simon Willison 在 Talking Postgres 播客中分享了他对 AI 编码代理如何改变软件开发的看法。他提出了一个反直觉的观点：在 AI 代理的语境下，以代码行数衡量生产力是有意义的，因为人类工程师每天能产出的高质量代码存在硬性上限，而代理可以大幅突破这一限制，前提是代码质量保持不变。但他同时指出，新的瓶颈变成了认知容量——单个工程师无法在认知上掌控百倍增长的代码量，因此团队仍然必要。他还讨论了《人月神话》中的概念完整性问题，用温彻斯特神秘屋类比：当添加功能的成本从一周降到一小时，软件很容易长出许多奇怪而不协调的'房间'，最终破坏整体设计的一致性。他认为关键在于纪律，过去时间成本天然约束了冲动，现在则需要工程师主动保持克制。
